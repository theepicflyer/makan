# makan web app

SvelteKit (Svelte 5) single-page PWA, built to `build/` and served by the FastAPI backend (`makan.main`).

```bash
npm install
npm run dev      # Vite on :5173, proxies /api, /auth and /mcp to the backend on :8000
npm run check    # svelte-check, plus tsc for the service worker
npm run build    # writes build/, which the backend serves
```

- `src/lib/api.ts` sends `X-Makan: 1` on every request; the backend rejects writes without it.
- `src/lib/components/Assistant.svelte` posts to `/api/agent/turns` and reads the server-sent events from the response body.
- New top-level routes also need adding to `SPA_ROUTES` in `src/makan/main.py`.
- The UI is built on Burrow, the household design system ([its page](https://claude.ai/artifact/ShL86DzdjvTZDwRHLsd8L4)). `src/lib/burrow/` holds copies of its pieces: `tokens.css` (compiled from its `tokens.json`), `burrow.css` (its `bh-*` component classes) and `art.js` (the SVG drawings of the animals, traces, trails and habitats, from its `bundle.js` minus the React components). Re-sync those from the design system rather than editing them; the Svelte components beside them (`Habitat`, `Ring`, `Meter`, `Peek`…) port its React components and are ours to change. `TrailPath` is makan's own: one trail wandering down a screen behind its cards, showing in the gaps between them.
- App-specific classes (`mk-*`) and the Tailwind colour names (`bg-surface`, `text-ink-muted`, `text-accent`…) live in `src/routes/layout.css`. Use Burrow tokens, never raw colours; protein, carbs and fat are `--protein`, `--carbs` and `--fat`, and energy is makan's own `--energy` (tomato).
- Energy, protein, carbs and fat each have a symbol, `src/lib/components/NutrientIcon.svelte`: a flame, a drumstick, an ear of wheat and a drop, drawn as Burrow stickers in those colours. Use it wherever one of the four is named, never a letter (P, C, F) or a plain colour dot: before the word where there's room (meters, fields via `Field nutrient=`, table headers, tooltips), and on its own before the number where there isn't (`MacroAmounts` for a row's protein, carbs and fat; the flame before a row's calories). Pass `labelled` when no word beside it names the nutrient, so screen readers hear it. Sizes: 16 beside 14px text, 14 beside 12px labels and in `MacroAmounts`.
- Burrow's rules worth keeping when adding a screen: one habitat header and at most one full-size animal per screen (pick the animal by job: Bao for food and the assistant, Gali for history and search, Kayu for settings, editing and errors), one primary button, one trail that ends at the next action (wrap the cards in `TrailPath` with a gap between them, mark the next thing to do with `data-trail-end`, and keep anything inside it opaque or the trail shows through), and no emoji in UI text.
- Burrow is phone first and has no wider layouts, so makan adds two (`src/lib/state.svelte.ts` has a `MediaQuery` for each, for where a screen changes structure; plain `sm:`/`lg:` classes where it only changes size):
  - From 640px (Tailwind `sm`, `columns.current`): unfolded foldables (a Pixel Fold's inner screen is about 790 px wide; its cover screen stays a phone) and tablets. The page column fills the width and screens lay out in columns, while the bottom nav and Bao's docked composer stay as on a phone, so unfolding keeps them where they were; sheets become centred dialogs. Today puts the sunflower and macros in a sticky left column beside the meals, in equal halves; History is the desktop dashboard with its charts stacked; Foods and Settings use two columns.
  - From 1024px (Tailwind `lg`, `wide.current`): desktop. The bottom nav becomes `SideNav`, a rail with the same links (`src/lib/nav.ts`) and Bao peeking over its top edge; the page column widens to `max-w-6xl` and habitats round all four corners; Bao's composer (`Assistant inline`) moves into Today's left column; History is a 12-column dashboard that ends at the table of days.
  - Half-folded, Chrome reports the fold through the Viewport Segments API. In book posture (the fold top to bottom: `@media (horizontal-viewport-segments: 2)`, the `book:` variant, `book.current`) the two-column screens already split either side of it; the nav, composer, toasts and sheets keep to the left-hand segment (`--fold-right`); History swaps its dashboard for the phone's cards beside the tunnel of days; the food page and sign-in keep to the left. In tabletop (the fold across) sheets move to the top half (`--fold-bottom`, `--sheet-h`) and the rest already sits clear of it. To try it, DevTools' foldable presets have a fold; in a script, the CDP's `Emulation.setDeviceMetricsOverride` takes a `displayFeature` (Playwright's own screenshots reset it, so capture with `Page.captureScreenshot`).
  - Each screen keeps one habitat and one trail at every size. Anything `fixed` positions itself with `--rail-w`, `--dock-h` (the bottom nav, 0 on desktop), `--composer-h` and `--fold-right` rather than hard-coded offsets. Charts in a grid cell need `min-w-0` and a `grid-cols-1` wrapper, or a chart measuring itself widens its column.
- Charts use `src/lib/components/BarChart.svelte`: Burrow sticker bars from one baseline, an optional dashed target and trend line, one tab stop with arrow keys and a live region, a tooltip on hover or tap, and click (not tap) to open what a bar stands for. Small multiples share `bind:active` inside an element marked `data-chart-group`.
- Motion: a new screen gets its entrance for free if its cards sit in a `TrailPath` (they rise in one after another); mark other lists `mk-stagger`, show totals with `Count` so they count up, and import transitions and `flip` from `src/lib/motion.ts` rather than `svelte/transition`, so reduced motion stays still. New CSS motion goes inside the `no-preference` block at the end of `layout.css`. The nav's current pill is one sliding blob (`slidingPill`), and the nav is the same element on every screen, so on day screens Bao ducks behind it (`mk-peek--away`) instead of the nav being swapped.
- Reminders: `src/lib/push.ts` subscribes this device (permission is asked from a tap) and re-registers it whenever Settings opens; signing out turns it off. The service worker shows each push as a notification tagged `reminder` and, on a tap, posts `{type: 'open', url}` to an open window (the layout navigates) or opens one. `static/icons/badge-96.png` is the white-on-transparent status bar icon Android wants.
- Fredoka and Figtree are bundled from `@fontsource` (Latin only) so the PWA works offline.
